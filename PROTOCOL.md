# Emergence Discovery Protocol — em_disco

**Version:** 1.0.0
**Status:** Frozen — changes require a major version bump
**Transport:** WebSocket (RFC 6455) over TCP or TLS
**Encoding:** JSON (UTF-8)

## 1. Connection

```
Endpoint: ws://<host>:<port>/ws?token=<jwt>
```

The `token` query parameter carries a JWT (HS256) for authentication.
Connections without a valid token are rejected with HTTP 401 before
the WebSocket upgrade.

## 2. Handshake

Two mandatory steps, in order. The agent MUST complete both before
it is eligible to receive queries.

### Step 1 — Register

```json
Agent -> Disco:  {"action": "register", "name": "<string>"}
Disco -> Agent:  {"status": "ok", "action": "registered"}
```

- `name` must be a non-empty UTF-8 string.
- `name` must be unique across all connected agents. If a name is
  already taken, the disco replies:
  `{"status": "error", "reason": "name_taken"}`
- The `name` MUST match the `sub` claim in the JWT. If it does not,
  the disco replies:
  `{"status": "error", "reason": "name_mismatch"}`

### Step 2 — Announce capabilities

```json
Agent -> Disco:  {"action": "agent_hello", "capabilities": ["<string>", ...]}
Disco -> Agent:  {"status": "ok", "action": "agent_registered", "capabilities": [...]}
```

- `capabilities` is a JSON array of non-empty strings, minimum 1 element.
- Sending `agent_hello` before `register` returns:
  `{"status": "error", "reason": "not_registered"}`

## 3. Query / Result Cycle

After the handshake, the agent enters an event loop.

### Query (disco -> agent)

```json
{"action": "query", "id": "<base64-string>", "body": "<query>"}
```

- `id` is a unique base64-encoded identifier generated by the disco.
- `body` is the raw query string from the client.

### Result (agent -> disco)

```json
{"action": "result", "id": "<query_id>", "data": <embryo | [embryo]>}
```

- The agent MUST respond with the same `id` it received.
- `data` can be a single embryo object or an array of embryos.
- The disco applies a global timeout (default 5000ms, configurable).
  Agents that do not respond in time are silently skipped.

## 4. Embryo Format

```json
{
  "type": "<string>",
  "properties": {
    "url": "<string>",
    "title": "<string>",
    "resume": "<string>",
    "domain": "<string>",
    "label": "<string>"
  }
}
```

- `type` is required. Examples: `"web"`, `"dns_a"`, `"rss"`, `"hackernews"`.
- All fields inside `properties` are optional.
- `properties` is extensible — agents may add custom fields.
- `properties.url` is used by clients for deduplication.

## 5. Error Messages

```json
{"status": "error", "reason": "<string>"}
```

| Reason | Condition |
|--------|-----------|
| `not_registered` | `agent_hello` sent before `register` |
| `name_taken` | Another agent already uses this name |
| `name_mismatch` | `name` in register does not match JWT `sub` claim |
| `invalid_json` | Payload could not be parsed |
| `unknown_action` | Unrecognized `action` field |

## 6. Heartbeat

The disco sends WebSocket ping frames (RFC 6455 §5.5.2).
Agents MUST respond with pong frames (handled automatically by
all compliant WebSocket libraries). Agents that fail to respond
within the idle timeout (default 60s) are disconnected.

## 7. Disconnection

When an agent disconnects (cleanly or via timeout), the disco
removes it from the agent registry. No explicit "goodbye" message
is needed.

## 8. HTTP Endpoints (read-only, no auth required)

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/query` | Submit a search query. Body: `{"query": "<string>", "capabilities": ["..."]}` |
| `GET` | `/registry` | List connected agents and capabilities |
| `POST` | `/mcp` | MCP JSON-RPC endpoint (tools: search, list_agents, list_capabilities) |
| `GET` | `/mcp` | MCP SSE channel |
| `GET` | `/` | Landing page UI |

These endpoints are rate-limited (token bucket, default 10 req/s per IP,
burst 30). Localhost clients have a higher limit (default 1000 req/s).
